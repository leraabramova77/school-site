# school-site

- Концепция, требования, этапы и журнал работ — в `docs/PRD.md`. Читай его перед началом работы.
- Документация для AI — `docs/ai/` (начни с `docs/ai/README.md`). Перед правкой сложного модуля читай его `README.md`
  и обновляй его, если меняешь устройство модуля.
- После каждого этапа или изменения требований обновляй PRD: статус этапа, коммит, новые решения и открытые вопросы.

## Как делаются изменения
- Новое требование → `/feature <требование>`, баг → `/bug <описание>`: Analyst → Developer → Tester → PR → Reviewer
  (см. `docs/ai/workflow.md`). **Мерж — агент сам, когда всё готово**: тестировщик PASS, ревью APPROVED (label
  `ai-approved`), зелёный CI, PR без конфликтов с `main` — сразу squash-мерж по `.claude/skills/merge/SKILL.md` и
  выкатка. За пользователем — утверждение ТЗ и «на экране то, что заказывал?», а также сбросы и удаление данных.
- Целиком, вместе с мержем и выкаткой, — `/flow feature "<…>"` / `/flow bug "<…>"`; только выкатка — `/flow release`;
  незавершённые прогоны — `/flow status`. Процессы — `.config/flows/*.yaml`, исполняет общий скилл `flow`.
  Claude запускать из папки проекта.
- Мелочи (опечатка, текст, документация) — без конвейера: ветка `chore/NNNN-…` + PR.
- **Конец сессии:** последнее сообщение любой сессии, где что-то менялось, — блок «🎉✅ СЕССИЮ МОЖНО ЗАКРЫВАТЬ ✅🎉»
  или «⛔ СЕССИЮ ПОКА НЕ ЗАКРЫВАТЬ» по шагу «8. Закрытие сессии» из `.claude/skills/feature/SKILL.md`. Согласованная и
  не выполненная работа — хвост, а не «Дальше»: пока она есть — только ⛔; она сразу пишется в `docs/PRD.md` →
  «Очередь задач».
- **Номер задачи:** сквозной `NNNN` — `pnpm -s wt next`. Ветка — `feature|bug|hotfix|chore/NNNN-short-slug`, коммиты и
  заголовок PR — `NNNN: что сделано` (по-русски). Строку задачи в `docs/HISTORY.md` добавить при заведении и закрыть
  (✅, PR) последним коммитом ветки. `docs/HISTORY.md` в контекст не подключать и целиком не читать — только дописывать.
- В `main` напрямую не коммитить и не пушить — только ветка + PR.
- **Каждая задача — в своём worktree:** `pnpm wt new feature/NNNN-slug` создаёт `~/Projects/my/<проект>_NNNN-slug`.
  Основной checkout всегда на чистом `main` — в нём только мерж и выкатка. Встроенные `EnterWorktree`/`--worktree` и
  голый `git worktree add` не использовать.
- Перед PR и ещё раз после правок по ревью задачу проверяет агент-тестировщик на локальном сервере её worktree
  (`pnpm wt serve`). После мержа и выкатки worktree удаляется (`pnpm wt remove <ветка>`); забытые удаляет хук
  `SessionStart` (`pnpm wt prune`).
- Перед отчётом о готовности: `pnpm check` и `pnpm build` зелёные.
- **`.env.example` и `.env.local` — одинаковые по структуре**: тот же порядок, разделы и комментарии. Значения из
  `.env.local` не выводить. Пустых значений нет: не нужно — `not-required`, ещё не получено — `required-not-set`.
