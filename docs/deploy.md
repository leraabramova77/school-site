# Выкладка

Постоянная ссылка для всех — **https://leraabramova77.github.io/school-site/app/**. Это страница-переход на GitHub
Pages. Она ведёт на адрес из переменной репозитория `APP_URL`. Ссылку можно добавить `?design=a|b|c`, чтобы
открыть нужный вариант оформления.

GitHub Pages умеет только раздавать файлы. Вход в netschool требует сервера: старый сайт не разрешает браузеру
обращаться к себе с чужих страниц (нет CORS), а пароль и сессия должны оставаться на сервере (ТЗ-1 §4).

## Сейчас: демо с этого компьютера (`pnpm demo`)

Сейчас это единственный рабочий вариант: с Vercel старый сайт недоступен (см. ниже).

| Команда | Что делает |
|---|---|
| `pnpm demo` | собирает свежий `main` в `../school-site-demo`, запускает `next start` (порт от 5100) и туннель Cloudflare, записывает адрес туннеля в `APP_URL` и обновляет Pages |
| `pnpm demo status` | показывает адреса и проверяет, что сервер и туннель живы (после перезагрузки — «НЕ РАБОТАЕТ») |
| `pnpm demo stop` | останавливает сервер и туннель |

- Туннель — бесплатный Cloudflare Quick Tunnel, без аккаунта. Программа `cloudflared` лежит в `~/bin`, скачана с
  github.com/cloudflare/cloudflared/releases, контрольная сумма сверена.
- Адрес туннеля меняется при каждом запуске, но ссылка на Pages остаётся той же: скрипт обновляет её сам.
- Компьютер должен быть включён и не засыпать. После перезагрузки нужно снова выполнить `pnpm demo`.
- `SESSION_SECRET` демо-сборки хранится в `../school-site-demo/.env.production`. Скрипт создаёт его один раз и не
  выводит, поэтому входы переживают пересборку.
- Лимит попыток входа хранится в памяти процесса, для одного сервера этого достаточно.

## Vercel (проверено 24.10.2026)

Проект подключён: аккаунт Леры (Hobby, бесплатно), проект `school-site`, адрес https://school-site-blush.vercel.app.
`SESSION_SECRET` добавлен в Production как Sensitive. Выкат делался из чистого экспорта `main` командой
`pnpm dlx vercel@65.2.0 --prod`. Страницы открываются, защита работает: без входа `/diary` → `/login`,
`/dev/*` → 404, чужой `Origin` → 403.

**Вход на Vercel не работает: netschool.refal.kg не отвечает серверам Vercel.** Из регионов fra1 (Франкфурт), bom1
(Мумбаи) и iad1 (Вашингтон) запрос к старому сайту обрывается по таймауту или с ошибкой сети, а с домашнего интернета
в Кыргызстане тот же запрос проходит. Похоже, сайт школы закрыт для адресов дата-центров или зарубежных адресов.
Поэтому `APP_URL` по-прежнему указывает на демо с компьютера.

Варианты, из которых выбирает Лера:

| Вариант | Цена | Минусы |
|---|---|---|
| Сервер на компьютере Леры (`pnpm demo`) | бесплатно | компьютер должен быть включён; адрес туннеля меняется при каждом запуске |
| Небольшой VPS в Кыргызстане | платно, цену уточнить у хостинга | нужна проверка, что с него netschool отвечает |
| Попросить школу или ИРТех открыть доступ для Vercel | бесплатно | зависит от них; у Vercel нет постоянных исходящих адресов на бесплатном тарифе |

Автовыкат из GitHub пока не подключён: `vercel git connect` требует, чтобы в аккаунте Vercel был привязан GitHub
(Account Settings → Authentication → **Connect** у GitHub; не проверено в интерфейсе).

Когда вход на Vercel заработает, перенаправить постоянную ссылку и остановить демо:

```sh
gh variable set APP_URL --body https://school-site-blush.vercel.app
gh workflow run pages.yml
pnpm demo stop
```

Дальше — по чеклисту прод-запуска (задача «Прод на Vercel» в `docs/PRD.md`): Upstash для лимита попыток входа на
нескольких экземплярах, заголовки безопасности, свой домен.
